## What's new

A pre-release on top of [v2.8.1](https://github.com/VivaLaVent/ps5-bazzite-deck/releases/tag/v2.8.1). Please report what you see, with the `SUMMARY` line of `ps5-report`.

- **Controllers paired in the PS5 OS connect in Linux, without pairing again.** The loader hands the PS5's Bluetooth pairings to Linux at every start, so a DualSense you use on the PS5 works in Linux right away and keeps working on the PS5. It needs **bazzite-bootc-loader v2.9** and applies while Linux uses the PS5's own Bluetooth address:
  - **Slim:** that's the default since v2.8.1, nothing to do.
  - **Original PS5 and PS5 Pro:** Linux uses its own address by default, with its own pairings, and nothing changes. To share the PS5's pairings instead: `ps5-bt-address off`, then restart. On an original PS5 that also allows warm restarts.
- **`bootc rollback` with warm restarts on:** a restart after a rollback came back on the version you were leaving. It now goes through the PS5 OS, and the loader starts the version you rolled back to.
- **Compute on the GPU** (ROCm/HIP, OpenCL): fresh allocations no longer cause page faults or lost data. Games aren't affected either way.
- Under the hood: the kernel package is built with the current upstream image builder, which now does the Wi-Fi driver steps this project used to patch in.

The pairings were tested upstream on firmware 13.60 with a DualSense and a DualSense Edge; other firmware and other devices are exactly what needs testing here.

## What to test

- **Slim, or any console after `ps5-bt-address off`:** with a DualSense paired in the PS5 OS, start Linux with the v2.9 loader and press the PS button: it should connect without pairing. Start the PS5 OS again: it should still connect there. `journalctl -b -u ps5-bt-import` shows how many pairings came over; include that line and your firmware version.
- **Original PS5 and Pro with the default address:** your Linux pairings keep working as before.
- **Original PS5:** Wi-Fi after a cold start, including a hidden network if you use one.
- ROCm or OpenCL, if you use them.

## bootc

### New install, or switching from Legacy

Switching means flashing the bootc image, which erases the drive: use a second drive, or copy off what you want to keep first. You need a USB drive or SSD of 64 GB or more.

1. Extract `ps5-bazzite-deck-bootc-v2.9.img.7z.001` with [7-Zip](https://www.7-zip.org) (not Windows' built-in extraction). The first line of `ps5-bazzite-deck-bootc-v2.9.img.sha256` is the `.img`'s checksum; on Windows, `certutil -hashfile ps5-bazzite-deck-bootc-v2.9.img SHA256` shows yours.
2. Flash the `.img` with [balenaEtcher](https://etcher.balena.io) (drives flashed with Rufus stopped in an emergency shell for several users; balenaEtcher fixed it). When Windows offers to format the drive afterwards, choose **Cancel**. On Linux with `sudo dd if=ps5-bazzite-deck-bootc-v2.9.img of=/dev/sdX bs=4M status=progress conv=fsync` (replace `/dev/sdX` with your drive).
3. Start it with `bazzite-bootc-loader-v2.9.elf`.

The first start takes a few minutes. A PS5 Pro reaches 60 compute units from the second start, once the loader has dumped its GPU firmware.

### Updating

This is a pre-release, on the **Beta** channel. On the PS5, in a terminal (Desktop Mode → **Konsole**) or over SSH (password `ps5`).

**On v2.6.2 or older,** or installed from one of their disk images: run this once first. It prints `ready to update`, and without it the update fails with "Failed to start ostree-finalize-staged.service":

```bash
sudo rm -f /etc/systemd/system/greenboot-set-rollback-trigger.service
printf '[Unit]\nDescription=No greenboot rollbacks on the PS5\n\n[Service]\nType=oneshot\nExecStart=/usr/bin/true\nRemainAfterExit=yes\n' | sudo tee /etc/systemd/system/greenboot-set-rollback-trigger.service >/dev/null
sudo systemctl daemon-reload && sudo systemctl start ostree-finalize-staged.service && echo "ready to update"
```

Then switch to Beta, which gets this release:

```bash
sudo bootc switch ghcr.io/vivalavent/ps5-bazzite-bootc:beta
```

Already on Beta: `sudo bootc upgrade`. For the PS5's pairings, also replace your loader with `bazzite-bootc-loader-v2.9.elf` from this release. It applies at the next start with the loader; on a PS5 Pro, start with the loader once more for its GPU firmware. Installed packages with `rpm-ostree install`? Use `sudo rpm-ostree upgrade` instead of `sudo bootc upgrade`.

**Back to the stable release:** the same `bootc switch` command with `:stable` instead of `:beta`. Steam's **Settings → System → OS Update Channel** does the same.

## Problems

- `sudo bootc rollback`, then power off or restart, and start with the loader.
- If a new version doesn't start at all: `ROLLBACK.txt` on the drive's boot partition explains how to start the previous one from a PC. That needs bazzite-bootc-loader.
- On a Legacy install: the undo command the update prints, or go back to [v1.8.9](https://github.com/VivaLaVent/ps5-bazzite-deck/releases/tag/v1.8.9) with the update command and `v1.8.9`.
- Report it in Discord with the file `ps5-report` saves.

## Known issues

- The pairing import doesn't work when the boot files are on the console's own storage (`ps5-m2-install --boot`): the loader writes the pairings there, where Linux can't read them.
- PS5 Hardware Control's **Restore on boot** (up to its version 1.5.0) loads your saved curve but leaves the console's fan control on until you apply a curve or preset; a fix is with its developer. Until then, `ps5_fan.curve=1` in `cmdline.txt` starts on the curve, and Restore on boot works.
- The first start after updating from v2.5.1 or older still uses the old VRAM size; the 6 GB applies from the next start with the loader. With the old 512 MB, Game Mode can show a garbled block in the top-left corner. Power off and start with the loader once more.
- A game that fills the whole VRAM can leave the display without room for its picture (`Failed to pin framebuffer: -ENOMEM` in the kernel log), reported with Ratchet & Clank: Rift Apart; under investigation. 4 GB in `vram.txt` (`0x100000000`) worked for that game on v2.5.1.

## Legacy

Installs from before v2.5 run the older Legacy form and update in place:
```
bash <(curl -fsSL https://raw.githubusercontent.com/VivaLaVent/ps5-bazzite-deck/main/tools/update-latest.sh) v2.9
```
Then power off and start with the loader. Switching to bootc is recommended (see bootc above).
