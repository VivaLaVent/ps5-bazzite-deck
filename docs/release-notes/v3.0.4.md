## What's new

Stable. Everything since [v3.0](https://github.com/VivaLaVent/ps5-bazzite-deck/releases/tag/v3.0), the previous Stable.

### Fixed

- **Games no longer drop out of Game Mode when VRAM fills up** (`Failed to pin framebuffer`: Returnal, Rift Apart, Miles Morales, Avowed and others). Game Mode keeps 512 MiB of VRAM for its own session; `ps5-report` shows `VRAM floor for Game Mode: system 512 MiB, session 512 MiB`. Steam's Force Composite is no longer needed for this. Found and tested by Delta and Max (all five games 3 of 3 at 4 GB VRAM), with two fixes traced on their consoles. Size: `echo 1024 | sudo tee /etc/ps5-bazzite-deck/vram-floor` (MiB; `0` off), then restart.
- **The coloured block on screen in Game Mode is gone** (original PS5 and Slim, [#78](https://github.com/VivaLaVent/ps5-bazzite-deck/issues/78)). It came from Game Mode's own compositor running on DirectMesh; now only Steam and the games use DirectMesh, so Mesh shaders stay. If you ran `ps5-directmesh off` because of the block, switch it back with `ps5-directmesh on`.
- **Monitors at 75 Hz, and old PC modes such as 800x600 and 1280x1024, show a picture** (FLAVA3 HDMI chip). Found by PS5-CachyOS.
- **Original PS5 consoles that report GPU 1002:13fc get DirectMesh too.** This later revision was missing from the list.

### New

- **The loader follows its upstream:** soniciso1's loader with the official one merged in, including MastaG's fix (a pairing slot the console can't read no longer drops all the other pairings) and the official fix for system software 10.xx. Use `bazzite-bootc-loader-v3.0.4.elf`.
- **A kernel switch, off by default, for the case where a game still drops out:** `amdgpu.ps5_scanout_reserve` keeps part of VRAM for the picture itself. See Known issues.

## What to test

- A game that dropped out of Game Mode before: does it run, including the Steam overlay (PS button) opened several times?
- Original PS5 and Slim: is the coloured block gone, with HDR on and off?

## bootc

### New install

A USB drive or SSD of 64 GB or more; flashing erases it.

1. Extract `ps5-bazzite-deck-bootc-v3.0.4.img.7z.001` with [7-Zip](https://www.7-zip.org). The first line of `ps5-bazzite-deck-bootc-v3.0.4.img.sha256` is the image's SHA-256.
2. Flash the `.img` with [balenaEtcher](https://etcher.balena.io), not Rufus. If Windows offers to format the drive, choose **Cancel**.
3. Start it with `bazzite-bootc-loader-v3.0.4.elf`. The first start takes a few minutes.

### Switching from Legacy

Flash a new install, or convert in place with the converter from v2.16.2, keeping users, games and Flatpaks: [wiki](https://wiki.ps5-linux.eu/updating/legacy).

### Updating

`sudo bootc upgrade`, or Steam's update button. It applies at the next start with the loader. Use `bazzite-bootc-loader-v3.0.4.elf` from this release: a PS5 Pro on system software 13.00 needs it for its GPU.

Stable follows the release marked **Latest**, Beta the newest pre-release: `sudo bootc switch ghcr.io/vivalavent/ps5-bazzite-bootc:beta` (or `:stable`), or Steam → Settings → System → OS Update Channel.

## Problems

- `sudo bootc rollback`, then restart with the loader.
- It doesn't start at all: follow `ROLLBACK.txt` on the drive's boot partition.
- Report it on Discord with the file `ps5-report` saves.

## Known issues

- PS5 Pro: a DualSense paired in the PS5 OS doesn't connect in Linux ([#73](https://github.com/VivaLaVent/ps5-bazzite-deck/issues/73)); the Pro keeps its own Linux Bluetooth address, pair once in Game Mode.
- DualSense over Bluetooth, late or ghost inputs in a Proton game: Bazzite Portal → Troubleshoot → switch InputPlumber off.
- `Failed to pin framebuffer`: games that dropped out of Game Mode now start, but one report saw it again after opening the Steam overlay many times (v3.0.2, before the VRAM floor fully worked). If it happens: `echo 512 | sudo tee /sys/module/amdgpu/parameters/ps5_scanout_reserve`, then start the game again, and tell us the game and the value. Keep VRAM at 4 GB or more.
- VERDE HDMI chip: no VRR yet.
- The clock is wrong for the first minute after a start, until network time arrives.
- Starting without the USB drive is experimental: [wiki](https://wiki.ps5-linux.eu/installation/m2-bazzite-deck#usb-free).
- M.2 installs from v2.11 or older can stop in an emergency shell after an update: [fix](https://wiki.ps5-linux.eu/troubleshooting/error-messages#ostree-boot-counter).
- A drive flashed before v2.11 doesn't start on PS5 system software 4.x: [fix](https://wiki.ps5-linux.eu/troubleshooting/error-messages#gpt-first-lba).
