## What's new

A pre-release on top of [v2.13](https://github.com/VivaLaVent/ps5-bazzite-deck/releases/tag/v2.13), the stable version. Please report what you see, with the `SUMMARY` line of `ps5-report`.

- **Mesh shaders on the original PS5 and Slim, per game (experimental).** Some D3D12 games need Mesh shaders ("DirectX 12 Ultimate") and don't start without them on these consoles. This release adds [DirectMesh](https://github.com/lonewolf0622/Mesh-Shaders-for-Rdna-1-) by lonewolf0622, written for the AMD BC-250, whose GPU is the same family as the PS5's. It comes as a second graphics driver that only the games you choose use: in Steam, the game's **Properties** → **Launch Options**, `ps5-directmesh %command%`. Every other game, the desktop and Game Mode keep the normal driver. On a PS5 Pro it changes nothing.
- DirectMesh has been tested on BC-250 hardware by its author, **not yet on a PS5**. If a game hangs with it, remove the launch option and the game is back on the normal driver. Reports either way are what this pre-release is for.

Everything else is as in v2.13: same kernel, same loader, same system.

## What to test

## bootc

### New install

You need a USB drive or SSD of 64 GB or more. Flashing erases it.

1. Extract `ps5-bazzite-deck-bootc-v2.14.img.7z.001` with [7-Zip](https://www.7-zip.org) (not Windows' built-in extraction). The first line of `ps5-bazzite-deck-bootc-v2.14.img.sha256` is the `.img`'s checksum; on Windows, `certutil -hashfile ps5-bazzite-deck-bootc-v2.14.img SHA256` shows yours.
2. Flash the `.img` with [balenaEtcher](https://etcher.balena.io) (drives flashed with Rufus stopped in an emergency shell for several users; balenaEtcher fixed it). When Windows offers to format the drive afterwards, choose **Cancel**. On Linux with `sudo dd if=ps5-bazzite-deck-bootc-v2.14.img of=/dev/sdX bs=4M status=progress conv=fsync` (replace `/dev/sdX` with your drive).
3. Start it with `bazzite-bootc-loader-v2.14.elf`.

The first start takes a few minutes. A PS5 Pro has its 60 compute units from the first start.

### Switching from Legacy

**In place, keeping users, games and Flatpaks.** On the Legacy install, in a terminal or over SSH, with at least 30 GB free on the system drive:

```bash
curl -fsSLO https://raw.githubusercontent.com/VivaLaVent/ps5-bazzite-deck/main/tools/legacy-to-bootc.sh
sudo bash legacy-to-bootc.sh            # checks only, changes nothing
sudo bash legacy-to-bootc.sh --apply    # downloads the Stable image (about 7 GB) and sets it up beside Legacy
```

Then power off and start with `bazzite-bootc-loader-v2.14.elf`. The first start moves your home folders and Flatpaks over.

- **Nothing of the Legacy system is deleted** until you run `sudo bash legacy-to-bootc.sh --cleanup` on the working bootc system, which frees about 20 GB.
- **If bootc doesn't start:** on a PC, copy `bzImage`, `initrd.img` and `cmdline.txt` from `legacy-backup/` on the drive's `boot` partition back to its top folder. Legacy starts again as before.
- **Not carried over:** Decky Loader and packages installed into the system; install them again. Options you added to `cmdline.txt` are kept.
- This script is new. A backup of anything you can't replace is a good idea before `--apply`.

**Or flash:** follow *New install* on a second drive, or on the same one after copying off what you want to keep.

### Updating

This is a pre-release, on the **Beta** channel. On the PS5, in a terminal (Desktop Mode → **Konsole**) or over SSH (password `ps5`):

```bash
sudo bootc switch ghcr.io/vivalavent/ps5-bazzite-bootc:beta
```

Already on Beta: `sudo bootc upgrade`. It applies at the next start with the loader. `bazzite-bootc-loader-v2.14.elf` is the same loader as v2.13's; either works. Installed packages with `rpm-ostree install`? Use `sudo rpm-ostree upgrade` instead of `sudo bootc upgrade`.

**Back to the stable release:** the same `bootc switch` command with `:stable` instead of `:beta`. Steam's **Settings → System → OS Update Channel** does the same.

## Problems

- `sudo bootc rollback`, then power off or restart, and start with the loader.
- If a new version doesn't start at all: `ROLLBACK.txt` on the drive's boot partition explains how to start the previous one from a PC. That needs bazzite-bootc-loader.
- Report it in Discord with the file `ps5-report` saves.

## Known issues

- **M.2 install in the emergency shell after an update** (`Couldn't find specified OSTree root '/sysroot//ostree/boot.1/…'`), on v2.11 or older: the boot partition names the right version under the wrong counter. Either way gets you back in, and nothing on the M.2 is lost:
  - **From a PC:** open `cmdline.txt` on the USB drive's `boot` partition and change the one number in `ostree=/ostree/boot.1/` to `0` (or `0` to `1` if it says `boot.0`). Leave the rest of the line as it is.
  - **In that shell,** with a USB keyboard (`nvme0n1p1` is the M.2's Linux partition; `blkid` lists it if yours differs):
    ```bash
    mount /dev/nvme0n1p1 /sysroot 2>/dev/null || mount -o remount,rw /sysroot
    cd /sysroot/ostree && { [ -e boot.1 ] || ln -s "$(readlink boot.0)" boot.1; [ -e boot.0 ] || ln -s "$(readlink boot.1)" boot.0; }
    cd / && umount /sysroot && reboot -f
    ```
  Then start with the loader and update to v2.13 or newer, which handles this by itself from then on.
- **An already flashed drive on PS5 system software 4.x** (any image before v2.11): fix it from a PC instead of flashing again. It changes one field, not your data, and only shows what it would do without `--apply`:
  ```bash
  curl -fsSLO https://raw.githubusercontent.com/VivaLaVent/ps5-bazzite-deck/main/bootc/tools/gpt-first-lba.py
  sudo python3 gpt-first-lba.py /dev/sdX --apply      # Linux; macOS: /dev/rdiskN after "diskutil unmountDisk diskN"
  ```
  On Windows, run it on the downloaded `.img` before flashing: `python gpt-first-lba.py ps5-bazzite-deck-bootc-vX.Y.img --apply`.
- **No HDR on consoles with the VERDE HDMI chip** (`ps5-report` names the chip on its first lines). The chip's HDR setup is unknown to every PS5 Linux kernel, from v1.8.9 on, so HDR is no longer offered there instead of coming out washed out.
- PS5 Hardware Control's **Restore on boot** (up to its version 1.5.0) loads your saved curve but leaves the console's fan control on until you apply a curve or preset; a fix is with its developer. Until then, `ps5_fan.curve=1` in `cmdline.txt` starts on the curve, and Restore on boot works.
- The first start after updating from v2.5.1 or older still uses the old VRAM size; the 6 GB applies from the next start with the loader. With the old 512 MB, Game Mode can show a garbled block in the top-left corner. Power off and start with the loader once more.
- A game that fills the whole VRAM can leave the display without room for its picture (`Failed to pin framebuffer: -ENOMEM` in the kernel log), reported with Ratchet & Clank: Rift Apart; under investigation. 4 GB in `vram.txt` (`0x100000000`) worked for that game on v2.5.1.
