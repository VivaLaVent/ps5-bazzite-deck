## What's new

Pre-release on top of [v3.0.1](https://github.com/VivaLaVent/ps5-bazzite-deck/releases/tag/v3.0.1).

- **Games no longer drop out of Game Mode when VRAM fills up** (`Failed to pin framebuffer`: Returnal, Rift Apart, Miles Morales, Avowed and others). Game Mode now keeps 512 MiB of VRAM for its own picture, so a game can't push it out. Steam's Force Composite is no longer needed for this. Found and tested by Delta and Max. To change the size: `echo 1024 | sudo tee /etc/ps5-bazzite-deck/vram-floor` (in MiB; `0` switches it off), then restart.
- **The coloured block on screen in Game Mode is gone** (original PS5 and Slim, #78). It came from Game Mode's own compositor running on DirectMesh; from now on only Steam and the games use DirectMesh, so Mesh shaders stay. If you ran `ps5-directmesh off` to get rid of the block, switch it back with `ps5-directmesh on`.
- **Original PS5 consoles that report GPU 1002:13fc get DirectMesh too.** This later revision was missing from the list, so those consoles stayed on the standard driver without Mesh shaders. `ps5-report` shows the GPU id on its Console line.

## What to test

- Original PS5 and Slim: with `ps5-directmesh on`, is the coloured block gone from Game Mode, with HDR on and off?
- A game that dropped out of Game Mode before: does it run now, including opening the Steam overlay (PS button)? `ps5-report` shows `VRAM floor for Game Mode: system 512 MiB, session 512 MiB` while Game Mode runs. Keep VRAM at 4 GB or more: with 1 GB some games hung in testing.
- Original PS5 with GPU 1002:13fc: `ps5-directmesh status` says `on`; do games that ran before still run?

## bootc

### New install

A USB drive or SSD of 64 GB or more; flashing erases it.

1. Extract `ps5-bazzite-deck-bootc-v3.0.2.img.7z.001` with [7-Zip](https://www.7-zip.org). The first line of `ps5-bazzite-deck-bootc-v3.0.2.img.sha256` is the image's SHA-256.
2. Flash the `.img` with [balenaEtcher](https://etcher.balena.io), not Rufus. If Windows offers to format the drive, choose **Cancel**.
3. Start it with `bazzite-bootc-loader-v3.0.2.elf`. The first start takes a few minutes.

### Switching from Legacy

Flash a new install, or convert in place with the converter from v2.16.2, keeping users, games and Flatpaks: [wiki](https://wiki.ps5-linux.eu/updating/legacy).

### Updating

`sudo bootc upgrade`, or Steam's update button. It applies at the next start with the loader. Use `bazzite-bootc-loader-v3.0.2.elf` from this release: a PS5 Pro on system software 13.00 needs it for its GPU.

Stable follows the release marked **Latest**, Beta the newest pre-release: `sudo bootc switch ghcr.io/vivalavent/ps5-bazzite-bootc:beta` (or `:stable`), or Steam → Settings → System → OS Update Channel.

## Problems

- `sudo bootc rollback`, then restart with the loader.
- It doesn't start at all: follow `ROLLBACK.txt` on the drive's boot partition.
- Report it on Discord with the file `ps5-report` saves.

## Known issues

- PS5 Pro: a DualSense paired in the PS5 OS doesn't connect in Linux ([#73](https://github.com/VivaLaVent/ps5-bazzite-deck/issues/73)); the Pro keeps its own Linux Bluetooth address, pair once in Game Mode.
- DualSense over Bluetooth, late or ghost inputs in a Proton game: Bazzite Portal → Troubleshoot → switch InputPlumber off.
- Some games drop out of Game Mode with `Failed to pin framebuffer` when VRAM is full: Rift Apart runs with Steam's Force Composite (see Option in What's new); Returnal, Avowed and Spider-Man: Miles Morales still need Desktop Mode.
- VERDE HDMI chip: no VRR yet.
- The clock is wrong for the first minute after a start, until network time arrives.
- Starting without the USB drive is experimental: [wiki](https://wiki.ps5-linux.eu/installation/m2-bazzite-deck#usb-free).
- M.2 installs from v2.11 or older can stop in an emergency shell after an update: [fix](https://wiki.ps5-linux.eu/troubleshooting/error-messages#ostree-boot-counter).
- A drive flashed before v2.11 doesn't start on PS5 system software 4.x: [fix](https://wiki.ps5-linux.eu/troubleshooting/error-messages#gpt-first-lba).
