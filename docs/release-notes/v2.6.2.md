## What's new

Everything since v2.5, the last stable release (v2.5.1 and v2.6.1 were pre-releases).

**bootc consoles on v2.5: run this once before updating.** On v2.5, every update and channel switch fails with "Failed to start ostree-finalize-staged.service". Run these three lines on the PS5, in a terminal or over SSH; it should print `ready to update`. The change stays through all later updates.

```bash
sudo rm -f /etc/systemd/system/greenboot-set-rollback-trigger.service
printf '[Unit]\nDescription=No greenboot rollbacks on the PS5\n\n[Service]\nType=oneshot\nExecStart=/usr/bin/true\nRemainAfterExit=yes\n' | sudo tee /etc/systemd/system/greenboot-set-rollback-trigger.service >/dev/null
sudo systemctl daemon-reload && sudo systemctl start ostree-finalize-staged.service && echo "ready to update"
```

- **PS5 Pro: games that went black now run.** Since v2.1.6 the Pro used a substitute for part of its GPU firmware (to fix DXVK D3D9 games), and that substitute hung D3D12 games such as Dragon's Dogma 2 in a GPU reset that never recovered. The Pro uses Sony's own firmware again, as up to v2.1.1. A D3D9 game that hangs at its first frame: add `ps5.viola_cp=cs2` to `cmdline.txt` to bring the substitute back.
- **PS5 Pro: 60 compute units on more firmware versions.** bazzite-bootc-loader is now built from soniciso1's loader, which dumps the Pro's GPU firmware on 11.00 to 11.60, 12.00, 12.02, 12.40, 12.70 and 13.20 to 13.60. Use the loader from this release.
- **PS5 Pro: faster AI upscaling.** The bootc image's Vulkan driver (RADV) now uses the Pro's int8 matrix instructions and its compute queue (Borchev's Mesa patch): FSR4's INT8 model runs about 3.6 times faster, which kept Dragon's Dogma 2 at 60 FPS with FSR4 frame generation. Base PS5s and Slims behave as before. `RADV_VIOLA_ML=0` in a game's launch options turns the new instructions off.
- **PS5 Pro: Bluetooth works again,** from a cold boot and after sleep, as in v2.1.x.
- **PS5 Pro: cooler and quieter.** Its CPU clock is left to its firmware again, as in v2.1.x, so the GPU's clock control is no longer blocked at idle, and the red `mp1` errors at startup are gone.
- **Quieter, calmer fan:** the console's own fan control with an 80 °C target is the default again, as in v1.8.9 (also during sleep and shutdown). The hwcon plugin and app still switch to a fan curve.
- **100 Hz modes** (1080p, 1440p and 4K at 100 Hz on consoles with the FLAVA3 HDMI chip) are back as an option: add `hdmi.modes_100hz=1` to `cmdline.txt`.
- **Bluetooth on most Slims** survives a warm reboot, and keeps its Linux-only address when the adapter is slow to come up at start (the DualSense couldn't connect then).
- **6 GB VRAM by default** on every console, new installs and existing ones (once; `vram.txt` on the boot partition changes it).
- **Starts in Desktop Mode.** New and existing installs start in the KDE desktop from now on. To start in Game Mode again, change the default session in Steam's settings in Game Mode.
- **Steam's own startup and suspend videos** instead of Bazzite's; videos you added yourself stay. New installs also keep Steam's own branding.
- **Steam works the same in Desktop Mode and Game Mode,** with Bazzite's own setup for both (Steam's update branch in Desktop Mode, the Return to Game Mode shortcut).
- **Update channels:** Steam's **Settings → System → OS Update Channel** offers **Stable** (the stable release's kernel) and **Beta** (the newest pre-release's), both of PS5 Bazzite Deck. Consoles still following an older release's fixed version move to Stable by themselves.
- **The system can move to the M.2,** bootc and Legacy alike: `sudo ps5-m2-install` copies the running system to the console's M.2 drive, shows its progress and checks that the system starts from there. Steps on the [wiki](https://wiki.ps5-linux.eu/installation/m2-install#ps5-bazzite-deck).
- **Legacy installs** started from an M.2 or another drive update in place again (the update refused with "this is not a PS5 Bazzite Deck install").
- **`ps5-report`** shows the VRAM in use next to the size in `vram.txt`, and the login banner names this image.

## bootc

### New install, or switching from Legacy

Switching means flashing the bootc image, which erases the drive: use a second drive, or copy off what you want to keep first. You need a USB drive or SSD of 64 GB or more.

1. Extract `ps5-bazzite-deck-bootc-v2.6.2.img.7z.001` with [7-Zip](https://www.7-zip.org) (not Windows' built-in extraction). The first line of `ps5-bazzite-deck-bootc-v2.6.2.sha256` is the `.img`'s checksum; on Windows, `certutil -hashfile ps5-bazzite-deck-bootc-v2.6.2.img SHA256` shows yours.
2. Flash the `.img` with [balenaEtcher](https://etcher.balena.io) (drives flashed with Rufus stopped in an emergency shell for several users; balenaEtcher fixed it). When Windows offers to format the drive afterwards, choose **Cancel**. On Linux with `sudo dd if=ps5-bazzite-deck-bootc-v2.6.2.img of=/dev/sdX bs=4M status=progress conv=fsync` (replace `/dev/sdX` with your drive).
3. Start it with `bazzite-bootc-loader-v2.6.2.elf`.

The first start takes a few minutes. A PS5 Pro reaches 60 compute units from the second start, once the loader has dumped its GPU firmware.

### Updating

Steam's update button (**Settings → System**) or `sudo bootc upgrade`. On v2.5, first run the three lines at the top of these notes. Restart, start with **this release's loader**, and start once more on a PS5 Pro.

## Problems

- `sudo bootc rollback`, then power off (not restart) and start with the loader.
- If a new version doesn't start at all: `ROLLBACK.txt` on the drive's boot partition explains how to start the previous one from a PC. That needs bazzite-bootc-loader.
- On a Legacy install: the undo command the update prints, or go back to [v1.8.9](https://github.com/VivaLaVent/ps5-bazzite-deck/releases/tag/v1.8.9) with the update command and `v1.8.9`.
- Report it in Discord with the file `ps5-report` saves.

## Known issues

- The first start after updating still uses the old VRAM size; the 6 GB applies from the next start with the loader. With the old 512 MB, Game Mode can show a garbled block in the top-left corner. Power off and start with the loader once more.
- A game that fills the whole VRAM can leave the display without room for its picture (`Failed to pin framebuffer: -ENOMEM` in the kernel log), reported with Ratchet & Clank: Rift Apart; under investigation. 4 GB in `vram.txt` (`0x100000000`) worked for that game on v2.5.1.

## Legacy

Installs from before v2.5 run the older Legacy form and update in place:
```
bash <(curl -fsSL https://raw.githubusercontent.com/VivaLaVent/ps5-bazzite-deck/main/tools/update-latest.sh) v2.6.2
```
Then power off and start with the loader. Switching to bootc is recommended (see bootc above).
