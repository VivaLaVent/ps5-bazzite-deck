## What's new

Everything since v2.7, the last stable release (v2.7.1 and v2.7.2 were pre-releases).

- **Async compute on the base PS5 and Slim.** Games can now use the GPU's compute queue next to rendering, as on the Pro. Linux hid it because it corrupted pictures; the fix found for the ASRock BC-250, the same GPU family, is in this image, and there it gave 20 to 25% more FPS in Cyberpunk 2077. If a game misbehaves, add `AMD_PS5_COMPUTE_QUEUE=0 %command%` to its launch options and report it. bootc installs only: Legacy installs don't have this image's Vulkan driver.
- **The fan runs on the console's own settings,** as on the PS5 OS. Up to v2.7, Linux gave the console's fan control its own table and an 80 °C target: quiet, but the chip ran warm, the fan spun up at power off and restart, and the PS5 OS could start with Linux's settings still in place. The fan may now be a little more audible at idle. PS5 Hardware Control works as before. Your own target: `sudo ps5-perf fan 70` (40 to 90 °C), back with `sudo ps5-perf fan default`.
- **1440p no longer off-centre** (FLAVA3 HDMI chip): 1440p at 60 Hz uses only the HDMI chip's own 1440p timing again, as up to v2.6. Faster 1440p modes are unchanged.
- **VRR on more displays** (FLAVA3): monitors that announce FreeSync but no HDMI VRR get the "Enable VRR" option again, and the VRR range is also read from the HDMI Forum block that newer TVs and monitors use.
- **Wi-Fi and Bluetooth on the first start after an update** (IW620 consoles, bootc): the Wi-Fi firmware is found the first time the driver loads, which ends the "host controller error" messages and missing Bluetooth until a restart.

## bootc

### New install, or switching from Legacy

Switching means flashing the bootc image, which erases the drive: use a second drive, or copy off what you want to keep first. You need a USB drive or SSD of 64 GB or more.

1. Extract `ps5-bazzite-deck-bootc-v2.7.3.img.7z.001` with [7-Zip](https://www.7-zip.org) (not Windows' built-in extraction). The first line of `ps5-bazzite-deck-bootc-v2.7.3.img.sha256` is the `.img`'s checksum; on Windows, `certutil -hashfile ps5-bazzite-deck-bootc-v2.7.3.img SHA256` shows yours.
2. Flash the `.img` with [balenaEtcher](https://etcher.balena.io) (drives flashed with Rufus stopped in an emergency shell for several users; balenaEtcher fixed it). When Windows offers to format the drive afterwards, choose **Cancel**. On Linux with `sudo dd if=ps5-bazzite-deck-bootc-v2.7.3.img of=/dev/sdX bs=4M status=progress conv=fsync` (replace `/dev/sdX` with your drive).
3. Start it with `bazzite-bootc-loader-v2.7.3.elf`.

The first start takes a few minutes. A PS5 Pro reaches 60 compute units from the second start, once the loader has dumped its GPU firmware.

### Updating

On the PS5, in a terminal (Desktop Mode → **Konsole**) or over SSH (password `ps5`).

**On v2.6.2 or older,** or installed from one of their disk images: run this once first. It prints `ready to update`, and without it the update fails with "Failed to start ostree-finalize-staged.service":

```bash
sudo rm -f /etc/systemd/system/greenboot-set-rollback-trigger.service
printf '[Unit]\nDescription=No greenboot rollbacks on the PS5\n\n[Service]\nType=oneshot\nExecStart=/usr/bin/true\nRemainAfterExit=yes\n' | sudo tee /etc/systemd/system/greenboot-set-rollback-trigger.service >/dev/null
sudo systemctl daemon-reload && sudo systemctl start ostree-finalize-staged.service && echo "ready to update"
```

Then update:

```bash
sudo bootc upgrade
```

It applies at the next start with the loader; on a PS5 Pro, start with the loader once more for its GPU firmware. Installed packages with `rpm-ostree install`? Use `sudo rpm-ostree upgrade` instead of `sudo bootc upgrade`.

**Stable or Beta:** Stable follows the release marked **Latest**, Beta the newest pre-release. Switch with this; it applies at the next start with the loader:

```bash
sudo bootc switch ghcr.io/vivalavent/ps5-bazzite-bootc:beta
```

`:stable` instead of `:beta` goes back to Stable. Steam's **Settings → System → OS Update Channel** does the same.

## Problems

- `sudo bootc rollback`, then power off (not restart) and start with the loader.
- If a new version doesn't start at all: `ROLLBACK.txt` on the drive's boot partition explains how to start the previous one from a PC. That needs bazzite-bootc-loader.
- On a Legacy install: the undo command the update prints, or go back to [v1.8.9](https://github.com/VivaLaVent/ps5-bazzite-deck/releases/tag/v1.8.9) with the update command and `v1.8.9`.
- Report it in Discord with the file `ps5-report` saves.

## Known issues

- The first start after updating still uses the old VRAM size; the 6 GB applies from the next start with the loader. With the old 512 MB, Game Mode can show a garbled block in the top-left corner. Power off and start with the loader once more.
- A game that fills the whole VRAM can leave the display without room for its picture (`Failed to pin framebuffer: -ENOMEM` in the kernel log), reported with Ratchet & Clank: Rift Apart; under investigation. 4 GB in `vram.txt` (`0x100000000`) worked for that game on v2.5.1.
- The firewall doesn't start (`firewall-cmd --state` says `failed`): the kernel lacks the NetBIOS helper that Fedora's default zone uses for its samba-client service. Fixed with the next kernel. Until then, this starts it without that service:
  ```bash
  sudo firewall-offline-cmd --zone=FedoraWorkstation --remove-service=samba-client
  sudo systemctl restart firewalld
  ```

## Legacy

Installs from before v2.5 run the older Legacy form and update in place:
```
bash <(curl -fsSL https://raw.githubusercontent.com/VivaLaVent/ps5-bazzite-deck/main/tools/update-latest.sh) v2.7.3
```
Then power off and start with the loader. Switching to bootc is recommended (see bootc above).
