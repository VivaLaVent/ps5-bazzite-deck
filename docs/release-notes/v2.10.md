## What's new

**The new stable version.** Everything since [v2.7.3](https://github.com/VivaLaVent/ps5-bazzite-deck/releases/tag/v2.7.3), the previous one:

**Slim owners: pair your controller once more after updating.** On the Slim, Linux and the PS5 OS now share one Bluetooth pairing: hold **PS + Create** until the light blinks fast, then pair it in Linux. With **bazzite-bootc-loader v2.10** from this release, a controller paired in the PS5 OS then connects in Linux without pairing again.

### Controllers and Bluetooth
- **Controllers paired in the PS5 OS connect in Linux, without pairing again.** The loader hands the PS5's pairings to Linux at every start. It needs bazzite-bootc-loader v2.10 and applies while Linux uses the PS5's own Bluetooth address: the default on the Slim. On an original PS5 or a Pro, Linux keeps its own address and pairings; `ps5-bt-address off` and a restart share the PS5's instead.
- **Slim:** the Linux-only Bluetooth address is off by default; it broke connections on several Slims ("setup has failed").
- **Original PS5 (IW620):** pairing completes when the controller asks for the new key a second time, devices with private addresses are recognized, and Wi-Fi comes up right after a warm restart and finds hidden networks.

### Fan and temperature
- **The console's own fan control holds the chip at 80 °C,** without the full-speed bursts that made the fan cycle, and above 85 °C the GPU no longer has to slow down. For a different target: `ps5_fan.target=70` in `cmdline.txt` (40 °C up to Sony's 91; lower means more fan), or `ps5_fan.curve=1` for the kernel's curve, around 60 °C at idle.
- A loud fan on the PS5 OS after Linux (left behind by versions up to v2.7.1) is fixed at the first start.

### Display
- **HDR on consoles with the VERDE HDMI chip** is no longer offered. It never worked on that chip, in no PS5 Linux kernel, and came out washed out. FLAVA3 consoles keep HDR as before.
- A fix from the PS5 Linux project for display updates with several planes, such as the performance overlay.
- **Help find out which display fixes are still needed:** four of them now have a switch, all on. The [test](https://github.com/VivaLaVent/ps5-bazzite-deck/blob/main/docs/testing.md#display-switches) takes a few minutes per switch.

### System
- **Linux 7.3.3.** Compute on the GPU (ROCm/HIP, OpenCL) no longer causes page faults or lost data; games aren't affected.
- **bootc:** `bootc rollback` with warm restarts on now starts the version you rolled back to; USB autosuspend is off, so the USB SSD the system runs from isn't put to sleep.
- **Stable stays stable:** the Stable channel gets only stable releases and Bazzite's updates. In Steam, **Settings → System → OS Update Channel** offers Stable and Beta.
- The firewall starts again.

## What to test

- **The display switches** on your TV, one at a time (see the link above).
- **Consoles with the VERDE chip and an HDR TV:** HDR is no longer offered in Game Mode or the desktop; the picture looks right.
- **FLAVA3 consoles where HDR looks washed out:** with HDR on, `sudo dmesg | grep 'hdmi: setup:'` after `echo 'file drivers/ps5/hdmi.c +p' | sudo tee /sys/kernel/debug/dynamic_debug/control`. `12 bpc YCbCr 4:2:2` is the HDR path; `8 bpc RGB` means Game Mode didn't ask for BT.2020 or the mode isn't 1080p60 or 4K60.
- **USB SSDs:** long downloads and games from the USB drive, with no freezes.

## bootc

### New install, or switching from Legacy

Switching means flashing the bootc image, which erases the drive: use a second drive, or copy off what you want to keep first. You need a USB drive or SSD of 64 GB or more.

1. Extract `ps5-bazzite-deck-bootc-v2.10.img.7z.001` with [7-Zip](https://www.7-zip.org) (not Windows' built-in extraction). The first line of `ps5-bazzite-deck-bootc-v2.10.img.sha256` is the `.img`'s checksum; on Windows, `certutil -hashfile ps5-bazzite-deck-bootc-v2.10.img SHA256` shows yours.
2. Flash the `.img` with [balenaEtcher](https://etcher.balena.io) (drives flashed with Rufus stopped in an emergency shell for several users; balenaEtcher fixed it). When Windows offers to format the drive afterwards, choose **Cancel**. On Linux with `sudo dd if=ps5-bazzite-deck-bootc-v2.10.img of=/dev/sdX bs=4M status=progress conv=fsync` (replace `/dev/sdX` with your drive).
3. Start it with `bazzite-bootc-loader-v2.10.elf`.

The first start takes a few minutes. A PS5 Pro reaches 60 compute units from the second start, once the loader has dumped its GPU firmware.

### Updating

On the PS5, in a terminal (Desktop Mode → **Konsole**) or over SSH (password `ps5`).

**On v2.6.2 or older,** or installed from one of their disk images: run this once first. It prints `ready to update`, and without it the update fails with "Failed to start ostree-finalize-staged.service":

```bash
sudo rm -f /etc/systemd/system/greenboot-set-rollback-trigger.service
printf '[Unit]\nDescription=No greenboot rollbacks on the PS5\n\n[Service]\nType=oneshot\nExecStart=/usr/bin/true\nRemainAfterExit=yes\n' | sudo tee /etc/systemd/system/greenboot-set-rollback-trigger.service >/dev/null
sudo systemctl daemon-reload && sudo systemctl start ostree-finalize-staged.service && echo "ready to update"
```

Then update:

```bash
sudo bootc upgrade
```

Or Steam's update button. It applies at the next start with the loader; on a PS5 Pro, start with the loader once more for its GPU firmware. For the PS5's pairings, also replace your loader with `bazzite-bootc-loader-v2.10.elf` from this release. Installed packages with `rpm-ostree install`? Use `sudo rpm-ostree upgrade` instead of `sudo bootc upgrade`.

**Stable or Beta:** Stable follows the release marked **Latest**, Beta the newest pre-release. Switch with this; it applies at the next start with the loader:

```bash
sudo bootc switch ghcr.io/vivalavent/ps5-bazzite-bootc:beta
```

`:stable` instead of `:beta` goes back to Stable. Steam's **Settings → System → OS Update Channel** does the same.

## Problems

- `sudo bootc rollback`, then power off or restart, and start with the loader.
- If a new version doesn't start at all: `ROLLBACK.txt` on the drive's boot partition explains how to start the previous one from a PC. That needs bazzite-bootc-loader.
- On a Legacy install: the undo command the update prints, or go back to [v1.8.9](https://github.com/VivaLaVent/ps5-bazzite-deck/releases/tag/v1.8.9) with the update command and `v1.8.9`.
- Report it in Discord with the file `ps5-report` saves.

## Known issues

- **No HDR on consoles with the VERDE HDMI chip** (`ps5-report` names the chip on its first lines). The chip's HDR setup is unknown to every PS5 Linux kernel, from v1.8.9 on, so HDR is no longer offered there instead of coming out washed out.
- The pairing import doesn't work when the boot files are on the console's own storage (`ps5-m2-install --boot`): the loader writes the pairings there, where Linux can't read them.
- PS5 Hardware Control's **Restore on boot** (up to its version 1.5.0) loads your saved curve but leaves the console's fan control on until you apply a curve or preset; a fix is with its developer. Until then, `ps5_fan.curve=1` in `cmdline.txt` starts on the curve, and Restore on boot works.
- The first start after updating from v2.5.1 or older still uses the old VRAM size; the 6 GB applies from the next start with the loader. With the old 512 MB, Game Mode can show a garbled block in the top-left corner. Power off and start with the loader once more.
- A game that fills the whole VRAM can leave the display without room for its picture (`Failed to pin framebuffer: -ENOMEM` in the kernel log), reported with Ratchet & Clank: Rift Apart; under investigation. 4 GB in `vram.txt` (`0x100000000`) worked for that game on v2.5.1.

## Legacy

Installs from before v2.5 run the older Legacy form and update in place:
```
bash <(curl -fsSL https://raw.githubusercontent.com/VivaLaVent/ps5-bazzite-deck/main/tools/update-latest.sh) v2.10
```
Then power off and start with the loader. Switching to bootc is recommended (see bootc above).
