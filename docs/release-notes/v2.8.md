## What's new

A pre-release on top of [v2.7.3](https://github.com/VivaLaVent/ps5-bazzite-deck/releases/tag/v2.7.3). Please report what you see, with the `SUMMARY` line of `ps5-report`.

- **The fan no longer cycles.** Linux forced the fan to full speed at 90 °C, just under the console's own 91 °C target, so under load it kept switching between loud and quiet. The console now handles its temperature itself, as on the PS5 OS.
- **A loud fan on the PS5 OS after Linux** (reported on a PS5 Pro): versions up to v2.7.1 could leave Linux's fan table in the console. v2.8 finds it at start and puts the console's own fan settings back. Start v2.8 once, power off, then check the fan on the PS5 OS, and tell us how it sounds.
- **`ps5-perf fan` is gone:** Linux no longer changes the console's fan target. For your own fan settings, use the curve in PS5 Hardware Control. A `FAN_TARGET` line in `/etc/ps5-bazzite-deck/perf.conf` is ignored.
- **The firewall starts again.** If you used the workaround from v2.7.3, this puts the removed service back: `sudo firewall-offline-cmd --zone=FedoraWorkstation --add-service=samba-client && sudo systemctl restart firewalld`.
- **Wi-Fi** (base PS5 with the IW620 chip): comes up right away after a warm reboot, finds hidden networks, and a connection that gets no answer fails at once instead of hanging.
- **Bluetooth** (base PS5 with the IW620 chip): pairing completes when the controller asks for the new key a second time, and paired devices that use private addresses are recognized.
- **Display:** a fix from the PS5 Linux project for display updates with several planes, such as the performance overlay. If you saw the 1440p artifact that went away after switching to Desktop Mode and back, check whether it still appears.
- **Linux 7.3.3** (was 7.3.1).
- **Stable stays stable:** consoles on the Stable channel now get only the stable release and Bazzite's updates. Until now they also got pre-release changes.

## What to test

- Idle, a game for 30 minutes, sleep, and power off; then start the PS5 OS and play as usual. In Desktop Mode, `watch -n1 sensors` shows the chip (`k10temp`) and fan (`ps5_fan`) temperatures: tell us the highest values in a game, and whether the game slows down when the chip is hot.
- PS5 Hardware Control: curve, full speed and Thermal Guard.
- Base PS5: pair a controller and a keyboard; Wi-Fi after a warm reboot (`ps5-warm-reboot on`); a hidden network.

## bootc

### New install

You need a USB drive or SSD of 64 GB or more. Flashing erases it. Coming from a Legacy install, which is no longer supported: the [v2.13 notes](https://github.com/VivaLaVent/ps5-bazzite-deck/releases/tag/v2.13) have the in-place switch.

1. Extract `ps5-bazzite-deck-bootc-v2.8.img.7z.001` with [7-Zip](https://www.7-zip.org) (not Windows' built-in extraction). The first line of `ps5-bazzite-deck-bootc-v2.8.img.sha256` is the `.img`'s checksum; on Windows, `certutil -hashfile ps5-bazzite-deck-bootc-v2.8.img SHA256` shows yours.
2. Flash the `.img` with [balenaEtcher](https://etcher.balena.io) (drives flashed with Rufus stopped in an emergency shell for several users; balenaEtcher fixed it). When Windows offers to format the drive afterwards, choose **Cancel**. On Linux with `sudo dd if=ps5-bazzite-deck-bootc-v2.8.img of=/dev/sdX bs=4M status=progress conv=fsync` (replace `/dev/sdX` with your drive).
3. Start it with `bazzite-bootc-loader-v2.8.elf`.

The first start takes a few minutes. A PS5 Pro reaches 60 compute units from the second start, once the loader has dumped its GPU firmware.

### Updating

This is a pre-release, on the **Beta** channel. On the PS5, in a terminal (Desktop Mode → **Konsole**) or over SSH (password `ps5`).

**On v2.6.2 or older,** or installed from one of their disk images: run this once first. It prints `ready to update`, and without it the update fails with "Failed to start ostree-finalize-staged.service":

```bash
sudo rm -f /etc/systemd/system/greenboot-set-rollback-trigger.service
printf '[Unit]\nDescription=No greenboot rollbacks on the PS5\n\n[Service]\nType=oneshot\nExecStart=/usr/bin/true\nRemainAfterExit=yes\n' | sudo tee /etc/systemd/system/greenboot-set-rollback-trigger.service >/dev/null
sudo systemctl daemon-reload && sudo systemctl start ostree-finalize-staged.service && echo "ready to update"
```

Then switch to Beta, which gets this release:

```bash
sudo bootc switch ghcr.io/vivalavent/ps5-bazzite-bootc:beta
```

Already on Beta: `sudo bootc upgrade`. It applies at the next start with the loader; on a PS5 Pro, start with the loader once more for its GPU firmware. Installed packages with `rpm-ostree install`? Use `sudo rpm-ostree upgrade` instead of `sudo bootc upgrade`.

**Back to the stable release:** the same `bootc switch` command with `:stable` instead of `:beta`. Steam's **Settings → System → OS Update Channel** does the same.

## Problems

- `sudo bootc rollback`, then power off (not restart) and start with the loader.
- If a new version doesn't start at all: `ROLLBACK.txt` on the drive's boot partition explains how to start the previous one from a PC. That needs bazzite-bootc-loader.
- Report it in Discord with the file `ps5-report` saves.

## Known issues

- PS5 Hardware Control's **Restore on boot** loads your saved curve but leaves the console's fan control on until you apply a curve or preset; a fix is with its developer.
- The first start after updating still uses the old VRAM size; the 6 GB applies from the next start with the loader. With the old 512 MB, Game Mode can show a garbled block in the top-left corner. Power off and start with the loader once more.
- A game that fills the whole VRAM can leave the display without room for its picture (`Failed to pin framebuffer: -ENOMEM` in the kernel log), reported with Ratchet & Clank: Rift Apart; under investigation. 4 GB in `vram.txt` (`0x100000000`) worked for that game on v2.5.1.
