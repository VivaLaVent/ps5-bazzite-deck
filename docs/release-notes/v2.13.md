## What's new

**The new stable version.** Everything since [v2.10](https://github.com/VivaLaVent/ps5-bazzite-deck/releases/tag/v2.10), the previous one.

**Legacy installs are no longer supported or updated.** If `ps5-report` says `legacy` on its Install line (an install from before v2.5), switch to bootc: a new script converts the install in place and keeps your users, games and Flatpaks, or flash the bootc image. See *Switching from Legacy* below.

**Replace your loader with `bazzite-bootc-loader-v2.13.elf`.** It now hands Linux what it reads from the PS5, and a PS5 Pro needs it for its GPU.

### PS5 Pro
- **60 compute units from the first start,** after installing and after every update, however the console starts. Before, the GPU firmware arrived one start late, and when it didn't arrive the Pro ran as a base PS5: 36 compute units, the GPU clock stuck, no GPU clock in PS5 Hardware Control. `ps5-report` shows `compute units: 60` under GPU.
- The `ps5.viola_cp=cs2` option is gone.

### Starting and updating
- **System on the M.2: no emergency shell after an update** ("Couldn't find specified OSTree root"). The update was complete; the boot partition and the M.2 named it under two different counters. The system now bridges that at the start. If your console is stuck there now, see Known issues.
- **Starts on PS5 system software 4.x.** There the PS5 couldn't read the drive ("unknown format"; the loader said "Couldn't find bzImage"). The cause, found by fitamix and confirmed by numitors, was one field in the drive's partition table. For a drive you already flashed, see Known issues.
- **Starting without a USB drive** (boot files in `/data/PS5/Linux` on the console's own storage): Wi-Fi on the original PS5 and controllers paired in the PS5 system work from the first start.

### Display
- **4K120 stays offered after switching between Game Mode and Desktop** (FLAVA3 HDMI chip). The check that withdraws 4K120 when the HDMI 2.1 link doesn't come up could keep watching a link that a mode change had already taken down, and then withdrew 4K120 until the next restart.

### Temperature, Wi-Fi and Bluetooth
- **Cooler and quieter at idle.** The CPU now comes down to its lowest clock (found and measured by fitamix), and the GPU no longer stays at 2 GHz after the CPU boosted. One console went from 62 °C to 46 °C at the desktop.
- **Wi-Fi on the original PS5 (IW620) no longer dies** when a phone on the same network opens a direct link to the console, such as Sunshine's web page. It also follows your access point's country, for the channels and transmit power allowed there.
- **Bluetooth:** the console's USB controller no longer goes into a power-saving state it doesn't return from.

### System
- **Steam → Settings → System → About:** OS Variant is `ps5-bazzite-deck`, and OS Build shows the channel and the release, such as `Stable 2.13`.

## What to test

- **PS5 Pro:** after the first start with the new loader, `ps5-report` shows `compute units: 60`.
- **The Legacy switch** (below): please report how it went, with the `SUMMARY` line of `ps5-report` from before and after.
- **Starting from `/data/PS5/Linux`:** Wi-Fi on an original PS5, and a DualSense paired in the PS5 system.

## bootc

### New install

You need a USB drive or SSD of 64 GB or more. Flashing erases it.

1. Extract `ps5-bazzite-deck-bootc-v2.13.img.7z.001` with [7-Zip](https://www.7-zip.org) (not Windows' built-in extraction). The first line of `ps5-bazzite-deck-bootc-v2.13.img.sha256` is the `.img`'s checksum; on Windows, `certutil -hashfile ps5-bazzite-deck-bootc-v2.13.img SHA256` shows yours.
2. Flash the `.img` with [balenaEtcher](https://etcher.balena.io) (drives flashed with Rufus stopped in an emergency shell for several users; balenaEtcher fixed it). When Windows offers to format the drive afterwards, choose **Cancel**. On Linux with `sudo dd if=ps5-bazzite-deck-bootc-v2.13.img of=/dev/sdX bs=4M status=progress conv=fsync` (replace `/dev/sdX` with your drive).
3. Start it with `bazzite-bootc-loader-v2.13.elf`.

The first start takes a few minutes. A PS5 Pro has its 60 compute units from the first start.

### Switching from Legacy

**In place, keeping users, games and Flatpaks.** On the Legacy install, in a terminal or over SSH, with at least 30 GB free on the system drive:

```bash
curl -fsSLO https://raw.githubusercontent.com/VivaLaVent/ps5-bazzite-deck/main/tools/legacy-to-bootc.sh
sudo bash legacy-to-bootc.sh            # checks only, changes nothing
sudo bash legacy-to-bootc.sh --apply    # downloads the Stable image (about 7 GB) and sets it up beside Legacy
```

Then power off and start with `bazzite-bootc-loader-v2.13.elf`. The first start moves your home folders and Flatpaks over.

- **Nothing of the Legacy system is deleted** until you run `sudo bash legacy-to-bootc.sh --cleanup` on the working bootc system, which frees about 20 GB.
- **If bootc doesn't start:** on a PC, copy `bzImage`, `initrd.img` and `cmdline.txt` from `legacy-backup/` on the drive's `boot` partition back to its top folder. Legacy starts again as before.
- **Not carried over:** Decky Loader and packages installed into the system; install them again. Options you added to `cmdline.txt` are kept.
- This script is new. A backup of anything you can't replace is a good idea before `--apply`.

**Or flash:** follow *New install* on a second drive, or on the same one after copying off what you want to keep.

### Updating

On the PS5, in a terminal (Desktop Mode → **Konsole**) or over SSH (password `ps5`).

**On v2.6.2 or older,** or installed from one of their disk images: run this once first. It prints `ready to update`, and without it the update fails with "Failed to start ostree-finalize-staged.service":

```bash
sudo rm -f /etc/systemd/system/greenboot-set-rollback-trigger.service
printf '[Unit]\nDescription=No greenboot rollbacks on the PS5\n\n[Service]\nType=oneshot\nExecStart=/usr/bin/true\nRemainAfterExit=yes\n' | sudo tee /etc/systemd/system/greenboot-set-rollback-trigger.service >/dev/null
sudo systemctl daemon-reload && sudo systemctl start ostree-finalize-staged.service && echo "ready to update"
```

Then update:

```bash
sudo bootc upgrade
```

Or Steam's update button. It applies at the next start with the loader. Replace your loader with `bazzite-bootc-loader-v2.13.elf` from this release: it hands Linux the PS5 Pro's GPU firmware, the Wi-Fi firmware and the PS5's pairings, and with an older loader a PS5 Pro runs as a base PS5. Installed packages with `rpm-ostree install`? Use `sudo rpm-ostree upgrade` instead of `sudo bootc upgrade`.

**Stable or Beta:** Stable follows the release marked **Latest**, Beta the newest pre-release. Switch with this; it applies at the next start with the loader:

```bash
sudo bootc switch ghcr.io/vivalavent/ps5-bazzite-bootc:beta
```

`:stable` instead of `:beta` goes back to Stable. Steam's **Settings → System → OS Update Channel** does the same.

## Problems

- `sudo bootc rollback`, then power off or restart, and start with the loader.
- If a new version doesn't start at all: `ROLLBACK.txt` on the drive's boot partition explains how to start the previous one from a PC. That needs bazzite-bootc-loader.
- Report it in Discord with the file `ps5-report` saves.

## Known issues

- **M.2 install in the emergency shell after an update** (`Couldn't find specified OSTree root '/sysroot//ostree/boot.1/…'`), on v2.11 or older: the boot partition names the right version under the wrong counter. Either way gets you back in, and nothing on the M.2 is lost:
  - **From a PC:** open `cmdline.txt` on the USB drive's `boot` partition and change the one number in `ostree=/ostree/boot.1/` to `0` (or `0` to `1` if it says `boot.0`). Leave the rest of the line as it is.
  - **In that shell,** with a USB keyboard (`nvme0n1p1` is the M.2's Linux partition; `blkid` lists it if yours differs):
    ```bash
    mount /dev/nvme0n1p1 /sysroot 2>/dev/null || mount -o remount,rw /sysroot
    cd /sysroot/ostree && { [ -e boot.1 ] || ln -s "$(readlink boot.0)" boot.1; [ -e boot.0 ] || ln -s "$(readlink boot.1)" boot.0; }
    cd / && umount /sysroot && reboot -f
    ```
  Then start with the loader and update to v2.13, which handles this by itself from then on.
- **An already flashed drive on PS5 system software 4.x** (any image before v2.11): fix it from a PC instead of flashing again. It changes one field, not your data, and only shows what it would do without `--apply`:
  ```bash
  curl -fsSLO https://raw.githubusercontent.com/VivaLaVent/ps5-bazzite-deck/main/bootc/tools/gpt-first-lba.py
  sudo python3 gpt-first-lba.py /dev/sdX --apply      # Linux; macOS: /dev/rdiskN after "diskutil unmountDisk diskN"
  ```
  On Windows, run it on the downloaded `.img` before flashing: `python gpt-first-lba.py ps5-bazzite-deck-bootc-vX.Y.img --apply`.
- **No HDR on consoles with the VERDE HDMI chip** (`ps5-report` names the chip on its first lines). The chip's HDR setup is unknown to every PS5 Linux kernel, from v1.8.9 on, so HDR is no longer offered there instead of coming out washed out.
- PS5 Hardware Control's **Restore on boot** (up to its version 1.5.0) loads your saved curve but leaves the console's fan control on until you apply a curve or preset; a fix is with its developer. Until then, `ps5_fan.curve=1` in `cmdline.txt` starts on the curve, and Restore on boot works.
- The first start after updating from v2.5.1 or older still uses the old VRAM size; the 6 GB applies from the next start with the loader. With the old 512 MB, Game Mode can show a garbled block in the top-left corner. Power off and start with the loader once more.
- A game that fills the whole VRAM can leave the display without room for its picture (`Failed to pin framebuffer: -ENOMEM` in the kernel log), reported with Ratchet & Clank: Rift Apart; under investigation. 4 GB in `vram.txt` (`0x100000000`) worked for that game on v2.5.1.
