## What's new

Pre-release on top of [v2.16](https://github.com/VivaLaVent/ps5-bazzite-deck/releases/tag/v2.16).

- **Bluetooth as in v2.15.** On the original PS5 and the Pro, Linux uses its own Bluetooth address again, so the DualSense needs one pairing in Linux (in Game Mode), separate from the PS5 OS's. The Slim keeps sharing the PS5 OS's pairing. v2.16 shared it on every console, but on a Pro the imported pairing didn't connect ([#73](https://github.com/VivaLaVent/ps5-bazzite-deck/issues/73)); sharing had only been tested on the Slim.
- **If you paired a controller in Linux on v2.16** (original PS5, Pro): pair it once more in Game Mode after updating.
- **The VRAM scanout test is removed.** The `amdgpu.sg_display=1` it needed stops the PS5 from starting (thanks doopz93). If you added it: remove it from `cmdline.txt` on the boot partition from a PC, then `sudo rpm-ostree kargs --delete=amdgpu.sg_display=1 --delete=amdgpu.ps5_scanout_gtt=1`.

## What to test

- Original PS5 and Pro: pair the DualSense in Game Mode; does it reconnect by itself after a restart? `ps5-report` shows `Linux-only address applied` on its Bluetooth line.
- Slim: does the DualSense still connect without pairing?
- **A game that works in Desktop Mode but drops out of Game Mode** with `Failed to pin framebuffer` (Rift Apart, Returnal, Predecessor on DX12): Game Mode → Settings → System → Enable Developer Mode, then Developer → **Force Composite**. Game Mode then copies the game's picture instead of showing its buffer directly, which needs a free block of VRAM. Does the game start, and at what frame rate?

## bootc

### New install

A USB drive or SSD of 64 GB or more; flashing erases it.

1. Extract `ps5-bazzite-deck-bootc-v2.16.1.img.7z.001` with [7-Zip](https://www.7-zip.org). The first line of `ps5-bazzite-deck-bootc-v2.16.1.img.sha256` is the image's SHA-256.
2. Flash the `.img` with [balenaEtcher](https://etcher.balena.io), not Rufus. If Windows offers to format the drive, choose **Cancel**.
3. Start it with `bazzite-bootc-loader-v2.16.1.elf`. The first start takes a few minutes.

### Switching from Legacy

In place, keeping users, games and Flatpaks: [wiki](https://wiki.ps5-linux.eu/updating/legacy). Or flash a new install.

### Updating

This pre-release is on the **Beta** channel: `sudo bootc switch ghcr.io/vivalavent/ps5-bazzite-bootc:beta`, or `sudo bootc upgrade` if you are on Beta already. Then start with the loader. A PS5 Pro on 13.00 needs the loader from v2.16 or newer.

Back to Stable: the same `bootc switch` with `:stable`, or Steam → Settings → System → OS Update Channel.

## Problems

- `sudo bootc rollback`, then restart with the loader.
- It doesn't start at all: follow `ROLLBACK.txt` on the drive's boot partition.
- Report it on Discord with the file `ps5-report` saves.

## Known issues

- Bazzite's performance profile can't start the LAVD scheduler: our kernel is built with pahole 1.30. The rest of the profile works.
- Games dropping out of Game Mode with `Failed to pin framebuffer`: VRAM is full. See *What to test*; 6 GB VRAM (the default) or 5 GB is the safe setting.
- The clock is wrong for the first minute after a start, until network time arrives.
- Starting without the USB drive is experimental: [wiki](https://wiki.ps5-linux.eu/installation/m2-bazzite-deck#usb-free).
- PS5 Pro: the CPU stays at 3.2 GHz.
- VERDE HDMI chip: no HDR.
- M.2 installs from v2.11 or older can stop in an emergency shell after an update: [fix](https://wiki.ps5-linux.eu/troubleshooting/error-messages#ostree-boot-counter).
- A drive flashed before v2.11 doesn't start on PS5 system software 4.x: [fix](https://wiki.ps5-linux.eu/troubleshooting/error-messages#gpt-first-lba).
