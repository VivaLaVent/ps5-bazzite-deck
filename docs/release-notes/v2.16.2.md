## What's new

Pre-release on top of [v2.16.1](https://github.com/VivaLaVent/ps5-bazzite-deck/releases/tag/v2.16.1).

- **Original PS5: one DualSense pairing for the PS5 and Linux again.** v2.16.1 switched it off on every console but the Slim; your reports show it works on the original PS5. Only the Pro keeps its own Linux address, because the shared pairing doesn't connect there ([#73](https://github.com/VivaLaVent/ps5-bazzite-deck/issues/73)). To choose yourself: `ps5-bt-address on` or `off`, then restart.
- **PS5 Pro: CPU boost to 3.5 GHz as an option:** `ps5-perf pro-boost on` (off again with `off`). It is the console's own boost, confirmed by two Pro owners. Off by default because it adds heat.
- **InputPlumber is off.** This service for handhelds replayed DualSense inputs late in Proton games over Bluetooth (ghost inputs; found by Sween Wolf). Bazzite Portal → Troubleshoot switches it back on.
- **The console's Bluetooth no longer shuts down after a burst of USB activity,** and `Salina poller: lock busy, rescheduling` no longer floods the screen. The driver for the console's own USB controller, which Bluetooth is on, gave up after 32 events in one pass and stayed dead until a restart. From the official PS5 kernel.
- **The graphics driver follows Bazzite to Mesa 26.2.7.**
- `ps5-report` no longer hangs while an update is downloading, and shows whether Wi-Fi is switched off.

## What to test

- Original PS5: after updating, pair the DualSense in the PS5 OS (or keep its PS5 pairing) and start Linux with the loader: does it connect without pairing? If you paired it in Linux on v2.16.1, remove that pairing in the Bluetooth settings first.
- PS5 Pro: `ps5-perf pro-boost on`, then a game for 15 minutes. `ps5-report` afterwards: the SoC temperature on the Fan line, and whether the GPU section shows `limiting the clock`.
- After a game crashes in Game Mode: does Game Mode come back by itself, and does the controller still work? `sudo dmesg | grep -iE "salina|xhci.*(died|dying)"` should stay empty.
- A game that works in Desktop Mode but drops out of Game Mode with `Failed to pin framebuffer`: Game Mode → Settings → System → Enable Developer Mode, then Developer → **Force Composite**. Rift Apart starts with it; Returnal, Avowed and Spider-Man: Miles Morales don't yet.

## bootc

### New install

A USB drive or SSD of 64 GB or more; flashing erases it.

1. Extract `ps5-bazzite-deck-bootc-v2.16.2.img.7z.001` with [7-Zip](https://www.7-zip.org). The first line of `ps5-bazzite-deck-bootc-v2.16.2.img.sha256` is the image's SHA-256.
2. Flash the `.img` with [balenaEtcher](https://etcher.balena.io), not Rufus. If Windows offers to format the drive, choose **Cancel**.
3. Start it with `bazzite-bootc-loader-v2.16.2.elf`. The first start takes a few minutes.

### Switching from Legacy

In place, keeping users, games and Flatpaks: [wiki](https://wiki.ps5-linux.eu/updating/legacy). Or flash a new install.

### Updating

This pre-release is on the **Beta** channel: `sudo bootc switch ghcr.io/vivalavent/ps5-bazzite-bootc:beta`, or `sudo bootc upgrade` if you are on Beta already. Then start with the loader. A PS5 Pro on 13.00 needs the loader from v2.16 or newer.

Back to Stable: the same `bootc switch` with `:stable`, or Steam → Settings → System → OS Update Channel.

## Problems

- `sudo bootc rollback`, then restart with the loader.
- It doesn't start at all: follow `ROLLBACK.txt` on the drive's boot partition.
- Report it on Discord with the file `ps5-report` saves.

## Known issues

- Bazzite's performance profile can't start the LAVD scheduler: our kernel is built with pahole 1.30. The rest of the profile works.
- Games dropping out of Game Mode with `Failed to pin framebuffer`: VRAM is full. See *What to test*; 6 GB VRAM (the default) or 5 GB is the safe setting.
- The clock is wrong for the first minute after a start, until network time arrives.
- Starting without the USB drive is experimental: [wiki](https://wiki.ps5-linux.eu/installation/m2-bazzite-deck#usb-free).
- PS5 Pro: the CPU stays at 3.2 GHz.
- VERDE HDMI chip: no HDR.
- M.2 installs from v2.11 or older can stop in an emergency shell after an update: [fix](https://wiki.ps5-linux.eu/troubleshooting/error-messages#ostree-boot-counter).
- A drive flashed before v2.11 doesn't start on PS5 system software 4.x: [fix](https://wiki.ps5-linux.eu/troubleshooting/error-messages#gpt-first-lba).
