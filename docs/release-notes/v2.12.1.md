## What's new

A pre-release on top of [v2.12](https://github.com/VivaLaVent/ps5-bazzite-deck/releases/tag/v2.12). Please report what you see, with the `SUMMARY` line of `ps5-report`.

- **4K120 no longer disappears after switching between Game Mode and Desktop** (original PS5 and Slim with the FLAVA3 HDMI chip). When the HDMI 2.1 link doesn't come up, the system stops offering 4K120 so you don't end on a black screen; that stays as it is. But the check behind it could keep watching a link that a mode change had already taken down, and then withdrew 4K120 until the next restart. It now stops when a mode change begins.

Everything from v2.12 is in: M.2 installs starting after an update, and the About page showing the variant, channel and release.

## bootc

### New install

You need a USB drive or SSD of 64 GB or more. Flashing erases it. Coming from a Legacy install, which is no longer supported: the [v2.13 notes](https://github.com/VivaLaVent/ps5-bazzite-deck/releases/tag/v2.13) have the in-place switch.

1. Extract `ps5-bazzite-deck-bootc-v2.12.1.img.7z.001` with [7-Zip](https://www.7-zip.org) (not Windows' built-in extraction). The first line of `ps5-bazzite-deck-bootc-v2.12.1.img.sha256` is the `.img`'s checksum; on Windows, `certutil -hashfile ps5-bazzite-deck-bootc-v2.12.1.img SHA256` shows yours.
2. Flash the `.img` with [balenaEtcher](https://etcher.balena.io) (drives flashed with Rufus stopped in an emergency shell for several users; balenaEtcher fixed it). When Windows offers to format the drive afterwards, choose **Cancel**. On Linux with `sudo dd if=ps5-bazzite-deck-bootc-v2.12.1.img of=/dev/sdX bs=4M status=progress conv=fsync` (replace `/dev/sdX` with your drive).
3. Start it with `bazzite-bootc-loader-v2.12.1.elf`.

The first start takes a few minutes. A PS5 Pro reaches 60 compute units from the second start, once the loader has dumped its GPU firmware.

### Updating

This is a pre-release, on the **Beta** channel. On the PS5, in a terminal (Desktop Mode → **Konsole**) or over SSH (password `ps5`).

**On v2.6.2 or older,** or installed from one of their disk images: run this once first. It prints `ready to update`, and without it the update fails with "Failed to start ostree-finalize-staged.service":

```bash
sudo rm -f /etc/systemd/system/greenboot-set-rollback-trigger.service
printf '[Unit]\nDescription=No greenboot rollbacks on the PS5\n\n[Service]\nType=oneshot\nExecStart=/usr/bin/true\nRemainAfterExit=yes\n' | sudo tee /etc/systemd/system/greenboot-set-rollback-trigger.service >/dev/null
sudo systemctl daemon-reload && sudo systemctl start ostree-finalize-staged.service && echo "ready to update"
```

Then switch to Beta, which gets this release:

```bash
sudo bootc switch ghcr.io/vivalavent/ps5-bazzite-bootc:beta
```

Already on Beta: `sudo bootc upgrade`. It applies at the next start with the loader; on a PS5 Pro, start with the loader once more for its GPU firmware. Installed packages with `rpm-ostree install`? Use `sudo rpm-ostree upgrade` instead of `sudo bootc upgrade`.

**Back to the stable release:** the same `bootc switch` command with `:stable` instead of `:beta`. Steam's **Settings → System → OS Update Channel** does the same.

## Problems

- `sudo bootc rollback`, then power off or restart, and start with the loader.
- If a new version doesn't start at all: `ROLLBACK.txt` on the drive's boot partition explains how to start the previous one from a PC. That needs bazzite-bootc-loader.
- Report it in Discord with the file `ps5-report` saves.

## Known issues

- **M.2 install in the emergency shell after an update** (`Couldn't find specified OSTree root '/sysroot//ostree/boot.1/…'`), on v2.11 or older: the boot partition names the right version under the wrong counter. Either way gets you back in, and nothing on the M.2 is lost:
  - **From a PC:** open `cmdline.txt` on the USB drive's `boot` partition and change the one number in `ostree=/ostree/boot.1/` to `0` (or `0` to `1` if it says `boot.0`). Leave the rest of the line as it is.
  - **In that shell,** with a USB keyboard (`nvme0n1p1` is the M.2's Linux partition; `blkid` lists it if yours differs):
    ```bash
    mount /dev/nvme0n1p1 /sysroot 2>/dev/null || mount -o remount,rw /sysroot
    cd /sysroot/ostree && { [ -e boot.1 ] || ln -s "$(readlink boot.0)" boot.1; [ -e boot.0 ] || ln -s "$(readlink boot.1)" boot.0; }
    cd / && umount /sysroot && reboot -f
    ```
  Then start with the loader and update to v2.12.1, which handles this by itself from then on.
- **An already flashed drive on PS5 system software 4.x** (any image before v2.11): fix it from a PC instead of flashing again. It changes one field, not your data, and only shows what it would do without `--apply`:
  ```bash
  curl -fsSLO https://raw.githubusercontent.com/VivaLaVent/ps5-bazzite-deck/main/bootc/tools/gpt-first-lba.py
  sudo python3 gpt-first-lba.py /dev/sdX --apply      # Linux; macOS: /dev/rdiskN after "diskutil unmountDisk diskN"
  ```
  On Windows, run it on the downloaded `.img` before flashing: `python gpt-first-lba.py ps5-bazzite-deck-bootc-vX.Y.img --apply`.
- **No HDR on consoles with the VERDE HDMI chip** (`ps5-report` names the chip on its first lines). The chip's HDR setup is unknown to every PS5 Linux kernel, from v1.8.9 on, so HDR is no longer offered there instead of coming out washed out.
- The pairing import doesn't work when the boot files are on the console's own storage (`ps5-m2-install --boot`): the loader writes the pairings there, where Linux can't read them.
- PS5 Hardware Control's **Restore on boot** (up to its version 1.5.0) loads your saved curve but leaves the console's fan control on until you apply a curve or preset; a fix is with its developer. Until then, `ps5_fan.curve=1` in `cmdline.txt` starts on the curve, and Restore on boot works.
- The first start after updating from v2.5.1 or older still uses the old VRAM size; the 6 GB applies from the next start with the loader. With the old 512 MB, Game Mode can show a garbled block in the top-left corner. Power off and start with the loader once more.
- A game that fills the whole VRAM can leave the display without room for its picture (`Failed to pin framebuffer: -ENOMEM` in the kernel log), reported with Ratchet & Clank: Rift Apart; under investigation. 4 GB in `vram.txt` (`0x100000000`) worked for that game on v2.5.1.
