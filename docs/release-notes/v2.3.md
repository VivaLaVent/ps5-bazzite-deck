## What's new

### A new way to keep Linux up to date on the PS5

Until now, updating meant running a script that replaced individual files, and going back meant installing an earlier kernel update by hand.

v2.3 ships the first **bootc image**: an image-based version of the same system, built the way Bazzite itself is built. An update downloads a complete new image in the background and takes effect at the next start. If something goes wrong, one command puts the previous image back. The PS5 kernel and all PS5-specific scripts are part of the image, so one update command keeps everything in step.

The **bazzite-bootc-loader** ships with every release, built from source: rmux's ps5-linux-loader plus patches that teach it the boot entries bootc writes, the basis for automatic fallback in a coming release. In v2.3 it starts the bootc image the same way as before, and going back is `sudo bootc rollback` plus a restart. It starts existing installs exactly as the standard loader does.

### Fixes for existing installs

**PS5 Pro: D3D9 games work.** DXVK D3D9 games (Fable Anniversary, NFS Underground) hung at the first 3D frame. The fix swaps in AMD's command-processor microcode, but it looked for uncompressed firmware files while Bazzite ships them compressed, so it never applied. It does now.

**PS5 Pro: 1 GB VRAM and an 80 °C GPU limit by default.** With 512 MB, demanding games ran out of video memory for the screen (`Failed to pin framebuffer: -ENOMEM`), and at 85 °C the console's firmware could cut power before Linux throttled. Both are set once; if you change them later, your settings stay.

**Original PS5 (IW620): Bluetooth no longer disappears.** When the Linux-only address doesn't stick after the adapter reset, the script used to retry right away, which hung the chip. Now Bluetooth keeps working on the PS5's own address, and `ps5-report` says `linux-only BT address: on, NOT applied`. A proper fix in the kernel is being tested.

## Already running PS5 Bazzite Deck

Update with the command under **Updating** below. Nothing else changes for you unless you choose to try bootc.

## Trying the bootc image

The bootc image is experimental, and trying it means reflashing.

1. Extract `ps5-bazzite-deck-bootc-v2.3.img.7z.001` with 7-Zip.
2. Flash the `.img`:
   - **Windows:** [Rufus](https://rufus.ie) in **DD mode**, or [Balena Etcher](https://etcher.balena.io)
   - **Linux / macOS:** `sudo dd if=ps5-bazzite-deck-bootc-v2.3.img of=/dev/sdX bs=4M status=progress` (replace `/dev/sdX` with your drive)
3. Start it with `bazzite-bootc-loader-v2.3.elf`.

From then on, the whole update process is:

```
sudo bootc upgrade
```

The new image downloads in the background and is used from the next start. To go back to the previous image: `sudo bootc rollback`, then restart.

**Known issue:** Wi-Fi may not come up on the very first start if its firmware wasn't staged yet. A second start fixes it.

Report bootc results in `#bazzite-bootc-testing` on Discord, not in `#bazzite-problems`.

## What to test

- **PS5 Pro:** a D3D9 game past its first 3D scene; `cat /efi/vram.txt` shows `0x40000000`; no `pin failed` in `sudo dmesg`.
- **Original PS5:** after a cold start Bluetooth is there (`bluetoothctl list`), even if `ps5-report` says the address was not applied.
- **bootc:** flash, start, Steam Gaming Mode loads; `sudo bootc status` shows the booted image; `sudo bootc upgrade` stages the next one.

## Sharing logs

`ps5-report`. For Bluetooth: `journalctl -u ps5-bt-addr -b --no-pager | tail -10`. For bootc: `sudo bootc status`.
